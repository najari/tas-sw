# M24-4 — 합성 트레이스 파싱 시도 + 원본 취약성 패턴 확정 (2026-10-18)

## 1. 합성 트레이스 데이터 교차 검증 — 원본 크래시 #3!

| 입력 | 원본 mcds_decoder.dll | 우리 mcdsdl.dll |
|---|---|---|
| 1KB 0x00 버퍼 (tdf=0, dm=5) | **크래시! (0xC0000005 — 액세스 위반!)** | rc 0x0 + 정직한 오류 ✓ |
| 1KB 0xFF 버퍼 | (도달 전 종료!) | rc 0x0 ✓ |
| 1KB 0xAA 버퍼 | (도달 전 종료!) | rc 0x0 ✓ |

→ **우리 구현 = 3/3 안전!** (원본은 첫 케이스에서 크래시!)

## 2. 원본 취약성 패턴 — 확정!

M24 시리즈에서 발견한 원본 크래시 3건:
1. `decode(NULL, 0, tdf=0x10, dm)` — NULL 역참조 (M24-2!)
2. `get_msg_str(합성 메시지 type=20/24)` — 설정 의존 경로 (M24-3!)
3. `decode(0x00 버퍼, 1KB)` — 트레이스 파싱 (M24-4!)

**패턴**: 원본 디코더는 **"엔진이 생성한 정상 상태"만 가정** — 합성/비정상 입력에는
취약 (방어 코드 부재!). 우리 구현은 모든 입력에 우아하게 대응 (문서화된 안전 우위!)

## 3. 함의 — 엔진 증분의 캘리브레이션 한계

- **엔진 심층부(피드/파서/코덱)의 교차 캘리브레이션 = 실데이터 필수!**
  - 원본이 합성 입력에서 크래시 → "정답지"를 얻을 수 없음 ✗
  - 실데이터(어댑터 해결 → M23-3!) 확보 시에만 [원본 ↔ 우리] 메시지 단위 비교 가능!
- **그때까지 가능한 것**:
  - 구조적 구현 (피드/파서의 상태 관리 — 안전한 자체 구현!) ✓
  - 디스패치/포맷팅 캘리브레이션 (M24-2/3 — 완료!) ✓
  - 엔진 아키텍처 정리 (클래스/파이프라인 — 완료!) ✓
