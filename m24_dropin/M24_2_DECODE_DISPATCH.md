## 2. 엔진 아키텍처 규명 (디컴파일 — C++ 클래스 구조!)

**클래스 (vftable/RTTI)**:
- `Decoder` (베이스!) → `CMcdsDecoder` (MCDS 본체!) · `DisasmDecoder` (디스어셈블!) ·
  `CMcdsConfigRegs`/`CMcdsConfigRegsA3g`/`...Mm`/`...A1g` (디바이스 패밀리별 설정 레지스터!)

**파이프라인** (mcdsdl_decode 실측!):
```
decode(trace_data, size_kb, tdf, dm)
  → FUN_18008a3f0 (상태 리셋)
  → [tdf=0x80: KEEP] FUN_180059690 (상태만 — DM 검사: CONT는 오류!)
  → [tdf=0x00]      FUN_1800599a0 (피드: size<<10!) → 코덱(압축 해제!) → 파서 → 후처리
  → [tdf=0x10]      FUN_1800597d0 (피드2 — 원본은 NULL에서 크래시!)
  → [그 외]         "This trace data format is not supported"
  → 크기 검사(20MB!) → 오류 카운터 검사("Trace file decodes with errors" — decoded > total!)
```

**계층별 규모 (점진 확장 로드맵!)**:
| 계층 | 함수 | 크기 | 상태 |
|---|---|---|---|
| 디스패치 | mcdsdl_decode | 68줄 | **✓ 구현 완료** (7/7 캘리브레이션!) |
| 피드/리셋 | FUN_1800599a0/8a3f0/59690/5997d0 | 23~66줄 | 다음 증분 (구조 단순!) |
| 파서 진입 | FUN_18005ade0 | 92줄 | 다음 증분 (메시지 배열 관리!) |
| 전/후처리 | FUN_18005bd30/a190 | 282/229줄 | 다음 증분 (메시지 타입 분기!) |
| **코덱** | FUN_180089080 + **거대 함수 23개** | 81줄+ | **장기** (MCDS 트레이스 압축!) |
| **디스어셈블** | DisasmDecoder 클래스 | (엔진 내부!) | **장기** (TriCore ISA!) |

**핵심 발견**: 엔진 상위 계층(디스패치~후처리) = **전부 소형~중형 (23~282줄!)** — 거대 함수 23개
(3998/3240/2409줄!) = 최심층(코덱 내부 루프 + 메시지 디코더들!). → **점진 확장이 구조적으로 가능** ✓

**메시지 배열**: 파서가 0x20바이트 단위 엔트리로 관리 (malloc(0x20×n!)) — 블록 0x1000/0x400 단위.
