# M24-W3 — Decoder 피드/파서 구조 평가 및 마무리 (2026-10-18)

## 1. 평가 결과 — 구조적 구현은 "불필요", 엔진은 "실데이터 게이트"

M24-2~4에서 규명한 대로:
- **디코더의 공개 API = 이미 완성** (25/25 — .mcds 파서/ELF/설정/상태/msgstr!)
- **피드/파서/코덱 = 엔진 내부** (외부에서 관측 불가 — 메시지가 나와야만 의미!)
- **엔진의 교차 캘리브레이션 = 원본이 합성 입력에서 크래시 → 실데이터 필수!**
  (M24-4: 크래시 3건 — decode(tdf=0x10)/msgstr(20/24)/synthetic trace!)

→ **결론: 피드/파서의 "안전 구조"만 따로 구현하는 것은 실효 가치가 없음**
  (공개 동작이 동일 = 검증 불가 — 원본도 정상 입력만 처리!)
→ **정직한 마무리: 엔진 전체를 실데이터 확보 시(M23-3!) 일괄 구현**이 옳음

## 2. W3에서 실제로 완료한 것 (안전성·견고성!)

1. **합성 입력 견고성 확보** (M24-4 — 원본 크래시 3건 대비 전부 안전!)
2. **엔진 아키텍처 문서화** (M24-2 — 클래스/파이프라인/계층 규모!)
3. **decode 디스패치·msgstr 캘리브레이션** (7/7 + 11/11!)
4. **실데이터 도착 시 즉시 구현 가능한 로드맵** (상위 계층 = 23~282줄 단위!)
