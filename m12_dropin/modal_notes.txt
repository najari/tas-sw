== 실패 모달 관찰 노트 (M12, 2026-10-18) ==

1. 사용자 Read 실패 직후, 클라이언트는 MODAL(모달 대화상자)을 띄우고 UI 이벤트 루프와
   PC 폴링을 블록한다 — 원본 mcdxdas.dll과 우리 mcd_tas.dll 모두 동일(클라이언트 코드 경로).

2. 이 환경에서 그 모달은 cua-driver 캡처(스크린샷)에 나타나지 않지만 실제로 존재·차단한다:
   - 실패 직후 로그가 'CALL qry_error_info' 줄에서 정지, CPU 사용 0(대기), 입력 미전달.
   - Escape 1회 전송 → 폴링 재개(로그 라인 1084→1942, PC 폴링/State 갱신 복귀) = 모달 닫힘.
   - 시각 자료: m12_modal.png (모달이 떠 있는 시점의 캡처 — 화면에는 보이지 않음).

3. Escape는 모달이 있을 때만 유효:
   - 모달이 없는 상태에서 Escape → 앱이 정상 종료됨(로그 'mcd_tas: exit, server closed').

4. 창 ID 변동: 모달/이벤트 계열 상호작용 후 메인 창의 window_id가 바뀌는 경우가 있음 →
   자동화는 상호작용 전마다 list_windows로 창 ID를 재조회해야 함.

5. 의미(정정): M6-era의 "원본 vs 우리 실패 표시 동작 차이(모달 재현 불가)" 결론은 오판이었다.
   모달은 양 스택에서 동일하게 표시·차단되며, 종전 관찰은 (a) 캡처에 렌더링되지 않음 +
   (b) 실패 후 추가 상호작용을 시도하지 않음 때문이었다. (정상 시절 crop_13의 모달과 동일한 것.)
